# JC-248 entitlement reconciliation design

## Authority and scope

The existing Store Blueprint Linear queue guides this work. JC-245, JC-246 and JC-247 are Done and implemented on canonical main `12cb5ee4107ca465c9b773b258c1cbae4754b2c7`. The user requested one stacked draft PR per ticket, so this branch follows JC-290 at `d1d60edfaa7f9ff24dec340cbee9e3f8fac234eb`, PR #216. Use one checkout and sequential implementation tasks with independent specification and quality reviews.

The latest durable AccessEffect is the desired access authority for its exact Subscription source. PostgreSQL grants are the actual state. Neither cache contents, job history, mutable plans nor Subscription status determine a repair target. Store has a scalar zero-or-one target; this work does not introduce NewYou target-set policy.

## Separate recovery and drift repair

Current nonterminal obligations continue through the accepted effective and non-effective executors. Their source fence handles stale work and permitted supersession. Keep that lifecycle separate from APPLIED drift repair.

Add a narrow system operation to repair an exact APPLIED effect. It owns its transaction, proves currentness through AccessEffectCurrentnessFence, and skips stale historical effects. A current non-APPLIED effect is rejected by this operation. The later source-level operation selects the current effect and routes nonterminal work to its existing executor.

For a current target, validate its source order-line and plan-revision IDs against the locked Subscription's funded pointers. Reuse the immutable PlanRevision target-pair validation. Do not require source-version equality with the aggregate; unrelated aggregate writes are legitimate. A mismatch fails closed before grant writes.

`Subscription.current_contract_change_id` is a queued future-instruction pointer. `persist_contract_change_tx` writes it when queueing and renewal consumption clears it. Existing AccessEffect producers capture that pointer as historical ordering context; it is not proof that the referenced change funded the effect's access. Leave establishment's pointer-equality check intact. Persisted execution and repair must instead preserve the effect's captured reference, validate a non-null reference's exact immutable ContractChange identity and Subscription ownership, and require its positive ordering version not to exceed the effect's source version. Do not require the live queued pointer, the reference's later status or its future target revision to equal the effect's funded revision. A later unpaid instruction cannot invalidate or replace a current target. Discovery joins this historical reference by its primary key after bounding the raw effect window.

Converge through the existing Entitlements source-convergence implementation. Add a narrow variant that first compares the locked source's active grants with the exact target. If already correct, return `already_converged` without writing grants. Otherwise use the existing target upsert, active non-target revoke and final-set validation, returning `repaired`. Both outcomes carry all source-user IDs needed for projection invalidation. This preserves independently valid sources and non-active historical evidence.

The APPLIED effect retains its entire persisted record. Do not reopen its lifecycle, change its fingerprint or source version, or manufacture another target. Use `subscription_source_reconciliation` as operational reason only for newly revoked drift. This reason does not reconstruct historical business policy.

After commit, use the shared notification wrapper and Entitlements invalidation/PubSub path. Propagate projection failures so a targeted worker retry can repeat invalidation even when grants are already converged. Cache is never mismatch authority. The existing cache has a 60-second TTL. This design does not claim durable PubSub delivery after operational retries exhaust.

## Bounded discovery

Verification walks immutable `(inserted_at, id)` keysets over APPLIED effects, using a fixed sweep high-water and a limit no greater than 500. Limit the scanned key window before checking latest-source authority, so a page of historical effects cannot trigger an unbounded search for current rows. Advance the cursor across the whole window even when every row is stale. Check currentness within that bounded query, then batch-read at most two active grants per current source. Two rows already prove a mismatch against Store's zero-or-one target. Healthy candidates must not cause per-source database round trips. Only mismatches enter isolated, fence-checked repair transactions.

Add the smallest required APPLIED verification index and keep its Ash snapshot/migration aligned. Use the existing source identity indexes for exact lookups. If the bounded batch read needs another index to avoid source-history work, include only that index and demonstrate the query shape with EXPLAIN. Do not introduce OFFSET, a global reconciliation lock, another pool, service or dependency.

An Oban sweep worker continues bounded pages and periodically restarts a complete sweep. Cursors record operational progress only. Losing a cursor can repeat work but cannot erase a target or make grants authoritative. Preserve finite execution failure as unresolved work, never manufactured APPLIED state. Reuse the existing nonterminal recovery lane and prove old/exhausted obligations remain discoverable.

Missing-effect inventory is diagnostic. Walk bounded Subscription primary-key windows before testing effect absence, with a fixed upper UUID captured at sweep start. Advance past healthy rows as well as missing-authority rows. The schema has no rollout or backfill marker, so absence alone cannot distinguish legacy rows, ordinary pre-access states and a violated transition invariant. Report that absence and available immutable provenance without granting, revoking, synthesizing effects or changing aggregate versions. A source-specific repair with no target fails closed. No one-time backfill is authorized by this design.

## Performance & Scaling Review

Reconciliation is warm operational work, with cold historical sweep candidates. Database targets and grants remain authoritative. Discovery is bounded and batched; repair is isolated per source under existing row locks.

The recorded tagged run used two local repetitions of 16 sources, each with 128 initially revoked historical grants. Timings and memory below describe that diagnostic run; later runs may differ. Healthy verification returned the requested 1 or 16 rows in two API queries in both repetitions. The one-row and 16-row calls recorded wall times of 27.200 ms and 6.718 ms in repetition one, then 2.948 ms and 3.718 ms in repetition two. RepoStats recorded queue/query/decode times in native units; these are diagnostic samples, not latency guarantees. A stale one-row page used one query in each repetition. Repairing one missing active target while preserving all 128 revoked grants used 10 queries in both repetitions, at 8.855 ms and 6.422 ms wall time. The locked provenance validation adds one fixed SQL read over the earlier executor path, and a non-null captured contract reference adds one exact historical primary-key read. Those reads have a cost.

Natural `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)` plans ran without planner overrides or a statistics refresh between fixture creation and both natural samples. The APPLIED window returned 16 rows in 0.328 to 0.398 ms, using sequential scans of local `access_effects` (16 returned, 18 filtered) and `subscriptions`, `plan_revisions_pkey` lookups, and sequential contract-change/currentness checks. In both repetitions the active-source batch returned one active row per source in 0.731 to 0.860 ms. PostgreSQL used `entitlement_grants_source_index`, read 129 index matches per source, then filtered 128 revoked rows from 80 exact heap blocks per source. This plan shows that the two-row result limit does not bound source-history work when statistics are stale. The authority inventory returned 16 rows in 0.146 to 0.159 ms, using local sequential scans of `subscriptions` and `access_effects`.

Before `ANALYZE`, PostgreSQL marked both `entitlement_grants_source_index` and `entitlement_grants_active_subscription_source_index` ready and valid. The partial index predicate was `(source_kind = 'subscription') AND (status = 'active')`. Catalog estimates were 5 rows for the table and both indexes, despite the live 2,069-row fixture. After the authorized test-only `ANALYZE entitlement_grants`, table estimates were 2,069 rows and 130 pages, source-index estimates were 2,069 rows and 10 pages, and active-index estimates were 21 rows and 17 pages. A fresh plan of the same source batch before `ANALYZE` again used `entitlement_grants_source_index`, reading 129 matches and filtering 128 history rows per source. Afterward it selected `entitlement_grants_active_subscription_source_index`, returned one active row per source without filtering history, and ran in 0.066 ms. This follow-up ran after both timed repetitions, so it did not change either API measurement.

These plans describe this small local fixture and its existing private diagnostic rows. They show that stale statistics explained the broad source-index scan in the pre-refresh plan, but they do not establish production index selection or bounds on internal dead-entry visits. The plans report returned rows and heap blocks; internal dead-entry visits remain UNMEASURED. No explicit statistics refresh occurred before the first natural plans; the only refresh was this labeled follow-up. Cache invalidation follows commit; the existing cache TTL remains 60 seconds. Oban jobs accelerate recoverable work but do not define completion. Telemetry must use IDs and bounded outcome classes, without source payloads or credentials.

## Runtime Resource Safety Review

The two measured repetitions each covered 16 sources and 128 revoked history rows per source. For measured calls, the dedicated task's process mailbox was zero before and after, RepoStats added no process-dictionary keys, telemetry handler counts stayed at zero, and the task ended outside a transaction. Process memory after the setup GC and before the measured call was 4,160 bytes for healthy/stale calls and 34,632 bytes for repair. Memory after the call ranged from 55,320 to 266,120 bytes for healthy/stale calls and from 426,744 to 426,896 bytes for repair; memory after explicit GC was 6,032 bytes for healthy/stale calls and 55,328 to 55,344 bytes for repair. Global GC counts ranged from 15 to 44 and reclaimed-word deltas from 18,003 to 219,183. Those are VM-wide diagnostics and cannot be assigned to the measured task.

Pool measurements retain the installed Ownership.Manager breakdown between the physical pool and ownership proxies. Before each call, the test waits for an idle snapshot whose summed ready count matches the configured pool size and whose checkout queues are empty. In these samples the split was three physical-pool connections and one owner-proxy connection. After the task returns, it polls for that exact source/count baseline. This accounts for the asynchronous proxy checkin and setup checkins that may still be settling. The test records baseline and return wait time and poll count. Seven return checks matched immediately in 13 to 26 microseconds. One needed one poll and 10.837 ms. It does not assume all configured connections report under the physical pool. The RepoStats and wall timers begin inside `Sandbox.unboxed_run`, after Sandbox ownership setup. The ownership proxy checks out a physical connection lazily on the first database operation, so the first API call may include that checkout. The timers exclude task scheduling and initial Sandbox ownership setup. They are not end-to-end worker latency.

Process memory before and after an explicit GC varied across samples. These two repetitions do not prove stable memory or no accumulation. Fixture cleanup confirmed zero owned subscription, effect and grant rows after each repetition, while leaving unrelated rows intact. Production capacity, multi-node behavior, allocator/RSS trends, arbitrary source-history fanout, internal dead-entry visits, and durable PubSub delivery after retry exhaustion remain UNMEASURED.
